## 零、审计结论（现状）

### 0.1 健康的部分

- `npm run typecheck` 通过；`npm run build` 通过（2026-11-06 21:02 复跑，`out/` 已更新）。
- 版本 **0.5.0**，源码约 70 个文件 / 1.15 万行；v1 闭环的 11 项功能已完成（见 [PROJECT.md](../PROJECT.md) 第七节）。
- 打包前置条件具备：`electron-builder` 的 nsis / winCodeSign 缓存已在 `%LOCALAPPDATA%\electron-builder\Cache`；`resources/icon.ico`、`icon.png`、`tray-icon.png` 齐全；better-sqlite3 原生模块已构建 → 具备离线打包条件。

### 0.2 阻碍发布的主要缺口

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **没有版本控制** | 项目及上级目录都不是 git 仓库（`git rev-parse` 失败） | 无回滚、无历史、误改无法恢复 |
| 2 | **0.5.0 从未打包** | `release/` 不存在；最后发布仍是 0.4.0 | 用户拿不到 v1 成果 |
| 3 | **仓库里有真实密钥** | `dev-run.log` 含旧接口真实 `key=`；`PROJECT.md` 只有占位符 | 一旦 git 提交会泄露 |
| 4 | **lock 版本不一致** | `package-lock.json` 版本 0.2.0，`package.json` 0.5.0 | 发布可复现性差 |
| 5 | **文档漂移** | `PROJECT.md` 仍写"保险库为开发机绝对路径""0.5.0 待打包"；仍以旧线索接口为例（官网已换 Halo 表单） | 交接/排查误导 |
| 6 | **安装版旧数据未迁移** | `%APPDATA%\desktop-pet` 仍启用旧轮询连接器（8001），`vault-settings.json` 指向 `F:\...` | 升级后可能出现"连不上/库找不到"的假象 |
| 7 | **无自动化测试、无 lint** | `package.json` 无 test/lint 脚本 | 只能人工验收，回归靠手点 |
| 8 | **MCP A 被外部信息阻塞** | 只有 `get_submission` 详情 schema；缺 endpoint / 鉴权 / 列表工具 | 不能排进 P0 |
| 9 | **MCP B 只有设计稿** | [docs/mcp-b-task-server.md](mcp-b-task-server.md) | 属于新增功能，不是发布阻塞 |

### 0.3 结论

代码本身已具备发布条件（构建/类型检查都过），**P0 的核心不是写功能，而是把"开发版可用"变成"可安装、可验收、可回滚的交付物"**。MCP A/B 都不应阻塞发布：A 卡在外部信息，B 是后续功能。
